Eligibility & Flow (Algorithm)

Pre-checks

Bank profile supports instant; amount ≤ sctInstAmountLimit.

Beneficiary reachable on chosen scheme (maintain a cached reachability directory; fallback to best-effort).

Original line status ∈ {submitted, accepted, rejected} and not settled.

Double-pay guard: no settled payment with the same disbursement key.

Create instant mini-batch

Generate new endToEndId ({sourceLineId}-R1), method=SCT_INST (or IRIS), submit via channel.

State management

On successful submission: mark source superseded=true.

On settlement (camt/push): log settled_at, update totals.

On failure: keep source state; log reason (timeout, unreachable, limit).

Cut-off guidance

If past SCT cut-off, recommend instant in UI automatically.

Edge Cases

Amount > limit: block with actionable message.

Beneficiary not reachable: block; propose standard SCT next business day.

Bank offline (no confirmation): show retry after N minutes; do not supersede original unless submission confirmed.

Reversal: If instant settled and original later also settles (bank error), flag double-pay incident → auto create reversal task.

BDD / Acceptance Tests

Happy path under 30s

Given a rejected SCT line (AC04)
When I re-issue as SCT Inst
Then a new instant batch is created and submitted
And settlement is received within 30s
And the original line is marked superseded
And double-pay guard remains satisfied


Guard against double-pay

Given an SCT line already settled
When attempting instant re-issue
Then the request is blocked with "Already settled" error


Instant limit exceeded

Given bank instant limit €100,000 and line amount €120,000
When I attempt re-issue
Then system blocks with "Over instant limit" and suggests SCT


Beneficiary unreachable

Given reachability check returns false
When I attempt re-issue
Then system blocks and logs 'unreachable'


Idempotency

Given the same reissue POST with identical idempotency key is retried
Then the same new batch id is returned and no duplicate lines are created


Timeout fallback

Given submission succeeded but no settlement within SLA
When 2 minutes pass
Then line remains 'accepted', operator sees 'awaiting confirmation', no supersede reversal occurs

Definition of Done

Re-issue flow available in cockpit + API; <30s median settle on sandbox.

Double-pay guard enforced globally; incident path wired.

Eligibility logic (limit, reachability) live with clear errors.

All BDD tests pass; event/webhook traces visible.

Metrics: Instant success rate, time-to-settle, fallback usage.
