if GET /api/login returns 401, something in your server stack is blocking the login endpoint before Passport can redirect (auth-guard, CSRF, or route/strategy mismatch). Here’s a precise set of checks + minimal diffs to get you to a guaranteed 302 redirect on /api/login.

1) Prove what’s returning 401 (don’t edit yet)

A. Dump registered strategies

node -e "const p=require('passport'); console.log('Strategies:', Object.keys(p._strategies))"
# Expect to see 'oidc' (or 'replitauth' if that’s your chosen name)


B. Trace middleware chain for /api/login
Add a temporary tap before your routers (remove later):

app.use((req,res,next)=>{
  if (req.path.startsWith('/api/login')) {
    console.log('[TAP]/api/login', { method:req.method, path:req.path });
  }
  next();
});


Now hit /api/login once and watch the logs. If you see your auth guard / MFA / CSRF middleware logging before Passport, that’s the culprit.

C. Confirm route methods

# You should get 302 (Location: https://replit.com/oidc/auth...)
curl -I "https://<REPLIT_DOMAIN>/api/login" -H "X-Forwarded-Host: <REPLIT_DOMAIN>" -k

2) Whitelist login & callback from guards (common cause of 401)

Make sure no authentication / MFA / CSRF middleware runs on these paths:

/api/login

/oauth2callback (GET + POST)

/api/auth/* (whoami/user/logout) — optional

Minimal guard wrapper
// before mounting any guard middlewares:
const AUTH_OPEN_PATHS = new Set([
  '/api/login',
  '/oauth2callback',
  '/api/auth/user',
  '/api/auth/status',
  '/api/auth/logout',
  '/api/whoami',
]);

function allowlist(paths:Set<string>) {
  return (req,res,next)=>{
    if (paths.has(req.path)) return next();
    return next('route');
  };
}

// Example: if you have a global auth guard or MFA middleware:
app.use(allowlist(AUTH_OPEN_PATHS), (req,res,next)=> mfaEnforcement.enforce()(req,res,next));
// Or if you have your own requireAuth:
app.use(allowlist(AUTH_OPEN_PATHS), (req,res,next)=> requireAuth(req,res,next));

CSRF (if any)

If you use csurf, add:

app.use(csurf({ ignoreMethods: ['GET', 'HEAD', 'OPTIONS'] })); // and/or
app.use((req,res,next)=>{
  if (AUTH_OPEN_PATHS.has(req.path)) return next();
  return csurfMiddleware(req,res,next);
});

CORS preflight

Ensure OPTIONS doesn’t 401:

app.options('/api/login', (req,res)=> res.sendStatus(204));

3) Make /api/login a guaranteed redirect (no 401)
Use a custom callback to log failures (temporarily), then 302:
// ensure this file uses the *same* strategy name you registered
const STRAT = 'oidc'; // or 'replitauth' — must match passport.use(name, strategy)

app.get('/api/login', (req, res, next) => {
  console.log('[AUTH][login] invoking passport.authenticate');
  passport.authenticate(STRAT, {
    scope: ['openid','email','profile','offline_access'],
    prompt: 'login consent'
  })(req, res, next);
});

// For hard debugging, swap to custom handler:
app.get('/api/login', (req,res,next)=>{
  passport.authenticate(STRAT, (err,user,info) => {
    if (err)  { console.error('[AUTH][login] err', err);  return res.status(500).json({ step:'login', err:String(err) }); }
    if (!user){ console.error('[AUTH][login] info', info); return res.status(401).json({ step:'login', info }); }
    // Normally /api/login should never “succeed” with a user — it should redirect to IdP.
    return res.status(500).json({ step:'unexpected', user:true });
  })(req,res,next);
});


Important: Use one consistent strategy name everywhere. If you passport.use('oidc', strategy), then every passport.authenticate call must use 'oidc'.

4) Ensure route ordering is correct

Place in this order:

app.use(session(...))

app.use(passport.initialize())

app.use(passport.session())

Public auth endpoints

GET /api/login

GET|POST /oauth2callback

GET /api/auth/user (whoami) etc.

Auth guards / MFA (with allowlist above)

Other API routes

Static/SPA catch-all (last)

If guards mount before /api/login and aren’t allowlisted, they’ll 401 it.

5) Quick success criteria

curl -I /api/login returns 302 with Location to https://replit.com/oidc/auth?...

Browser flow reaches /oauth2callback, your logs show verify called and session saved

Redirects to / or your actual dashboard route (ensure that route exists in SPA)

fetch('/api/auth/user', { credentials:'include' }) returns { authenticated: true, user: ... }

Common gotchas I’ve seen cause 401 on /api/login

A global requireAuth mounted on /api/* that didn’t whitelist /api/login.

An MFA middleware that requires a session user for all /api/*.

CSRF rejecting /api/login.

Strategy name mismatch in one place ('oidc' vs 'replitauth').

Multiple Express apps/instances (passport/session wired on one, routes on another).

Fixing the allowlist and making /api/login a pure Passport entrypoint usually resolves this immediately.
