| Area                       | Issue                                                                                                                         | Recommendation                                                                                                                                                                                                                                   |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Separation of Concerns** | Payroll logic is scattered across `greekPayrollCalculator.ts`, `modernPayrollEngine.ts`, and `PayrollBusinessRulesService.ts` | Create a clean 3-layer architecture:<br>**1. Domain (laws):** `core/greekRules/` — pure logic, no DB.<br>**2. Engine:** `engine/` — orchestrates payroll runs using domain logic.<br>**3. Infra:** `services/` — DB, API, compliance connectors. |
| **Law Versioning**         | No version-tracking of legal formulas (EFKA %, overtime %, allowances)                                                        | Move all law constants into `shared/law-constants.ts` with version/date per law. Use `LawRegistry` class to switch versions as laws change.                                                                                                      |
| **Schema Coupling**        | `shared/schema.ts` mixes payroll logic with DB structure                                                                      | Split: `schema.ts` for data shape only, `payrollDomain.ts` for logic types and enums. Improves testability and reduces accidental schema breaks.                                                                                                 |
