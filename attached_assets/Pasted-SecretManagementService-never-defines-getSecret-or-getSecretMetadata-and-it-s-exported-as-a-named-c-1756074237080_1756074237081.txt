SecretManagementService never defines getSecret or getSecretMetadata, and it’s exported as a named class (not default). Your rotation code is calling:

SecretManagementService.getSecret(...)

SecretManagementService.getSecretMetadata(...)

…so at runtime you get: “is not a function”.

Here’s a minimal, safe patch that fixes both the export mismatch and missing methods without touching the rest of your app.

1) Add compatibility methods + default export

Append these to the bottom of SecretManagementService (inside the class), then add the default export after the class:

  // --- Back-compat adapter methods (add inside the class) ---

  /** BACK-COMPAT: return just the plaintext value or null */
  static async getSecret(key: string): Promise<string | null> {
    const r = await this.retrieveSecret(key);
    return r.success ? (r.value ?? null) : null;
  }

  /** BACK-COMPAT: return metadata (or null) */
  static async getSecretMetadata(key: string): Promise<SecretMetadata | null> {
    const r = await this.retrieveSecret(key);
    return r.success ? (r.metadata ?? null) : null;
  }
}

// add this AFTER the class so default imports work too
export default SecretManagementService;


Why:

Rotation code that expects getSecret/getSecretMetadata now works.

If any file did import SecretManagementService from '...', it now resolves (you currently only have a named export).

2) (Optional) Normalize imports in the rotation service

Either default or named import will work after the patch. Pick one style and stick to it:

// Option A: default import (works after adding export default)
import SecretManagementService from '@/services/secretManagementService';

// Option B: named import (works already)
import { SecretManagementService } from '@/services/secretManagementService';


No further changes to rotation logic are required if it already calls .getSecret / .getSecretMetadata.

3) Prevent crashes while you roll out

Gate the scheduler and add a small runtime check (leave it in; it’s cheap):

if (process.env.ENABLE_SECRET_ROTATION !== 'true') {
  console.log('[secrets] rotation disabled by env');
} else {
  console.log('[secrets] methods:', {
    getSecret: typeof SecretManagementService.getSecret,
    getSecretMetadata: typeof SecretManagementService.getSecretMetadata,
    retrieveSecret: typeof SecretManagementService.retrieveSecret,
  });
  setInterval(() => {
    // wrap in try/catch to avoid unhandled timer exceptions
    rotateSafely().catch(e => console.warn('[secrets] rotation error:', e?.message || e));
  }, 60_000);
}


Set ENABLE_SECRET_ROTATION=false for now; flip to true after deploy once you see the log says both methods are function.

4) One tiny extra safeguard (Node ≥18)

You’re dynamically importing node-fetch. On Node 18+, global fetch exists. To avoid bundling confusion:

// replace in storeInVault / retrieveFromVault
const fetchFn: typeof fetch = (globalThis as any).fetch ?? (await import('node-fetch')).default;
const response = await fetchFn(url, {...});


This keeps it working in both environments.

5) Quick validation

Restart and check logs once:

You should see no more getSecret is not a function / getSecretMetadata is not a function.

Your SPA should render (the secret-rotation timer won’t be killing the process).

If the audit 42703 still appears, add the missing columns or map names as I noted earlier; it won’t block the frontend anymore.
