t’s still asking to “rename partners → status_page_subscriptions”, the deploy target DB still doesn’t have that table at the moment your migrator runs. Two common reasons:

You’re creating the table in a different DB (wrong connection/env in Replit deploy vs your local/SQL console).

You created it without schema qualification / wrong search_path (it landed in another schema, so the tool doesn’t see it).

Let’s kill this class of problems in one shot.

1) Verify you’re hitting the right DB (do this first)

Add this tiny startup log in your server before running migrations:

import pg from 'pg';
const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });
pool.query(`select current_database() db, current_user usr, current_schema schema, current_setting('search_path') sp, inet_server_addr() host;`)
  .then(r => console.log('[DB]', r.rows[0]))
  .catch(e => console.error('[DB] probe failed', e));


You should see the same db name/host you use in your SQL console. If not, fix DATABASE_URL in Replit Secrets.

2) Create everything idempotently, schema-qualified

Run this single SQL on the deploy target DB (Supabase/PG editor). It:

Ensures public is the schema used,

Pre-creates all “problem” tables,

Adds the missing completed_at column,

Is safe to re-run.

-- Always qualify with schema = public
set search_path to public;

create extension if not exists pgcrypto;

-- Helper: create a table only if missing
create or replace function public.ensure_table(p_table text, p_sql text)
returns void language plpgsql as $$
begin
  if not exists (
    select 1 from information_schema.tables
    where table_schema='public' and table_name=p_table
  ) then
    execute p_sql;
  end if;
end $$;

-- Helper: ensure a column exists (and optionally run extra SQL like indexes)
create or replace function public.ensure_column(
  p_table text, p_column text, p_type text, p_extra_sql text default null
) returns void language plpgsql as $$
begin
  if not exists (
    select 1 from information_schema.columns
    where table_schema='public' and table_name=p_table and column_name=p_column
  ) then
    execute format('alter table public.%I add column %I %s', p_table, p_column, p_type);
    if p_extra_sql is not null and length(p_extra_sql) > 0 then
      execute p_extra_sql;
    end if;
  end if;
end $$;

-- Updated-at trigger (reused)
create or replace function public.tg_set_updated_at()
returns trigger language plpgsql as $$
begin new.updated_at := now(); return new; end $$;

-- 1) status_page_incidents
select public.ensure_table('status_page_incidents', $SQL$
  create table public.status_page_incidents (
    id uuid primary key default gen_random_uuid(),
    title text not null,
    description text,
    severity text not null default 'info' check (severity in ('info','minor','major','critical')),
    status text not null default 'investigating' check (status in ('investigating','identified','monitoring','resolved')),
    started_at timestamptz not null default now(),
    resolved_at timestamptz,
    created_by uuid,
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now()
  );
  create index if not exists idx_spi_started_at on public.status_page_incidents(started_at desc);
  drop trigger if exists tr_spi_updated_at on public.status_page_incidents;
  create trigger tr_spi_updated_at before update on public.status_page_incidents
    for each row execute function public.tg_set_updated_at();
$SQL$);

table (

After you run it, quickly confirm:

select table_schema, table_name
from information_schema.tables
where table_schema='public' and table_name='status_page_subscriptions';


You must see a row. If not, you’re in the wrong DB or schema.

3) Make your migrator stop proposing renames

Depending on your stack:

Prisma

npx prisma db pull (sync to real DB)

Add models if needed

npx prisma migrate dev --name bootstrap_optional_tables

If production: npx prisma migrate deploy

If it still tries to rename partners, run npx prisma migrate resolve --applied <baseline> after generating a baseline diff from the current DB.

Drizzle

drizzle-kit introspect

Align schema files

drizzle-kit generate && drizzle-kit push

If a generated step suggests renames, delete them; keep CREATE/ALTER only.
