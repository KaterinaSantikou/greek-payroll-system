You’re hitting the same “create vs rename” heuristic, but this time for a column:
restore_tests.completed_at.

The clean fix is to add the column explicitly (idempotently) so the migrator stops asking.

Quick, safe SQL (PostgreSQL/Supabase)

Run this once (SQL editor / psql / migration file):

-- 1) Add the column only if it's missing
alter table public.restore_tests
  add column if not exists completed_at timestamptz;

-- 2) (Optional) backfill for already-finished rows if you have a status flag
-- adjust the WHERE clause to your schema
-- update public.restore_tests
--   set completed_at = coalesce(completed_at, updated_at)
-- where status in ('completed','success','done') and completed_at is null;

-- 3) (Optional) index to speed up queries by completion time
create index if not exists idx_restore_tests_completed_at
  on public.restore_tests (completed_at desc);

If you need it NOT NULL

Do it in two steps to avoid locking/errors:

-- step A: give a default just for the constraint change (optional)
alter table public.restore_tests
  alter column completed_at set default now();

-- step B: backfill any nulls first (tailor the value)
update public.restore_tests
  set completed_at = now()
where completed_at is null;

-- step C: enforce not-null
alter table public.restore_tests
  alter column completed_at set not null;

-- (optional) drop default if you don’t want new rows auto-filled
alter table public.restore_tests
  alter column completed_at drop default;

Stop future prompts like this (columns)

Add a tiny bootstrap function and call it for each required column:

create or replace function public.ensure_column(
  p_schema text,
  p_table  text,
  p_column text,
  p_type   text,
  p_alter_sql text
) returns void language plpgsql as $$
begin
  if not exists (
    select 1 from information_schema.columns
    where table_schema = p_schema
      and table_name  = p_table
      and column_name = p_column
  ) then
    execute format('alter table %I.%I add column %I %s', p_schema, p_table, p_column, p_type);
    if p_alter_sql is not null and length(p_alter_sql) > 0 then
      execute p_alter_sql;
    end if;
  end if;
end $$;

select public.ensure_column(
  'public','restore_tests','completed_at','timestamptz',
  'create index if not exists idx_restore_tests_completed_at on public.restore_tests (completed_at desc)'
);


This makes the migration idempotent and keeps your tool from offering risky rename operations.

Add field in your model:

Why this keeps popping up

Migration tools try to be clever: if they see a field in code but not in DB, they may suggest renaming an existing, similarly-typed column. By pre-creating the expected column (with ADD COLUMN IF NOT EXISTS) or making sure your ORM diff is based on a fresh introspection, you remove the ambiguity and the prompts stop.
