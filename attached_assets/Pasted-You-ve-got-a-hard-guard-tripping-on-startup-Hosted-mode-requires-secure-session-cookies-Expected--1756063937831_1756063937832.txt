You’ve got a hard guard tripping on startup:

Hosted mode requires secure session cookies. Expected: { secure: true, sameSite: 'none' }
Got: { secure: false, sameSite: 'lax' }


That means your app is running on the Replit hosted domain (HTTPS), but the session middleware is still using dev cookie flags.

Here’s a precise, minimal fix + verification commands.

1) Fix: session cookie flags in hosted mode

Unified diff (apply to where getSession() is defined, e.g. server/replitAuth.ts):

+export function getSession() {
+  const sessionTtl = 1000 * 60 * 60 * 24 * 7; // 7 days
+  // Hosted when Replit provides public domains
+  const isHosted = !!process.env.REPLIT_DOMAINS;
+  // Fallback to production heuristic, but prefer hosted flag
+  const isProd = isHosted || process.env.NODE_ENV === 'production';
+  return session({
+    secret: process.env.SESSION_SECRET!,
+    resave: false,
+    saveUninitialized: false,
+    cookie: {
+      httpOnly: true,
+      secure: isProd,                     // MUST be true on hosted (HTTPS)
+      sameSite: isProd ? 'none' : 'lax',  // MUST be 'none' on hosted
+      maxAge: sessionTtl,
+    },
+    store: sessionStore,
+    name: 'connect.sid',
+  });

Also ensure (once, before session() is mounted):

app.set('trust proxy', 1);


This lets Express/Session know it’s behind a proxy and to respect X-Forwarded-Proto=https—otherwise secure: true cookies won’t set.

2) Safety guard (keep, but adjust message)

If you keep the startup assertion, make it use isHosted:

const isHosted = !!process.env.REPLIT_DOMAINS;
const { secure, sameSite } = sessionOpts.cookie ?? {};
if (isHosted && (!secure || String(sameSite).toLowerCase() !== 'none')) {
  throw new Error(
    `Hosted mode requires secure session cookies. Expected {secure:true, sameSite:'none'}, got {secure:${!!secure}, sameSite:'${sameSite}'}`
  );
}

3) Verify with one-liners

After restart:

curl -I "https://$REPLIT_DOMAIN/api/login" -H "X-Forwarded-Host: $REPLIT_DOMAIN" | grep -i '^Location:'

# 3) Callback sets cookie with Secure; SameSite=None
# First authenticate in the browser, then:
curl -I "https://$REPLIT_DOMAIN/oauth2callback" -H "X-Forwarded-Host: $REPLIT_DOMAIN" | grep -i '^set-cookie:'

# Expect something like:
# Set-Cookie: connect.sid=...; Path=/; HttpOnly; Secure; SameSite=None


If you still see secure:false / sameSite:lax in your [SESSION] log, it means the old getSession() is still being used somewhere else. Search and ensure there’s only one session middleware:

rg -n "express-session|getSession\(\)" server
