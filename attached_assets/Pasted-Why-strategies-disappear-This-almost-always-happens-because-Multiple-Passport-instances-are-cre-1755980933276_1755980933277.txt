Why strategies “disappear”

This almost always happens because:

Multiple Passport instances are created (e.g., new Passport() somewhere, or importing different copies of the passport module from different paths/ts builds).

Hot reload / dual server processes re-require code and re-init Passport, so the instance you inspect is not the instance used by the router.

ESM/CJS boundary (e.g., mixing import passport from 'passport' and const passport = require('passport')) can load two copies in some toolchains.

Monorepo / transpiled output path causes one side to import from dist/… and the other from src/…, giving two module graphs.

We’ll eliminate all four.

1) Make Passport a true singleton
A) Create a single shared module

server/lib/passport.ts

// Always import THIS module wherever you need passport.
import passport from "passport";

// Hard guard: make sure no other copy is used
// (optional, but useful for debugging)
// @ts-ignore
if ((global as any).__passport_singleton && (global as any).__passport_singleton !== passport) {
  // eslint-disable-next-line no-console
  console.warn("Multiple passport instances detected");
}
// @ts-ignore
(global as any).__passport_singleton = passport;

export default passport;

B) Replace all imports

Search & replace everywhere:

- import passport from "passport";
+ import passport from "./lib/passport";


(or the right relative path from each file).
Do not do new (require('passport').Passport)() anywhere.

Dynamic callback override middleware (needed by some OIDC strategy impls)

// Before /api/login route:
function withDynamicCallback(req, _res, next) {
  const host =
    (req.headers["x-forwarded-host"] as string) ||
    (req.headers.host as string) ||
    req.hostname;
  const cb = `${req.protocol}://${host}/api/callback`;

  // Reach inside strategy and set callback for this request.
  // Works for openid-client/passport (keeps change local to this process).
  // @ts-ignore
  const strat: any = (passport as any)._strategies["replitauth"];
  if (strat) {
    if (strat._options) strat._options.callbackURL = cb;
    if (strat._callbackURL) strat._callbackURL = cb;
  }
  return next();
}

4) Kill duplication from dev servers (if any)

Only one dev server should run (no double nodemon / vite dev proxy that starts another server).

Ensure your .replit run command starts one Node process (the API).

If you run FE separately, use a proxy (Vite/Next rewrites) and don’t start a second API inside the FE dev tool.

6) If you still see “Unknown authentication strategy”

Checklist:

 All imports reference ./lib/passport singleton.

 No new Passport() anywhere.

 Only one server process.

 /debug/passport shows "replitauth" present just before you hit /api/login.

 Your OIDC app (Replit) has both callback URIs whitelisted (your Replit domain and localhost, if you test locally).

 NODE_ENV set, cookie sameSite present.

7) Optional: keep host-scoped approach (multi-host)

If you prefer host-scoped strategy names, register both your Replit domain and localhost variants and route by X-Forwarded-Host/Host. But the singleton change is still required to stop disappearing strategies.
